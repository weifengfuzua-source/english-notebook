# 可复用精读制作流程

## 用户日常入口

提供完整原文（文本、照片或 PDF）和精读总结，或粘贴到 `inbox/new-reading.md`，然后说：

> 处理今天的新精读并更新网站，按逐句翻译和正文点击批注标准。

用户不需要自己拆句、写 JSON 或维护页面。

## 1. 核对材料并保存原始输入

先读当前仓库、文章、学习记录和附件原文。照片或扫描必须实际查看。
原文不完整时保存草稿并说明缺失，不能从例句和总结推测全文。
保留用户原始材料；整理版与原始输入分开，不覆盖原始档案。

自动导入命令：

```powershell
node scripts/ingest.mjs --topic 社会与民生
```

此步骤生成文章 Markdown、初步学习记录以及待填的逐句数据，并归档输入；新文章始终为草稿。若没有原文，不创建逐句骨架。
同编号正式文章禁止覆盖；修改现有文章时直接修改已有内容源。

## 2. 整理文章与真实学习记录

- `content/articles/NNN-slug.md`：metadata、原文、错题复盘、重点词汇、词块、句式、薄弱点。
- `content/records/NNN-slug.json`：真实学习条目、实际原句、扫描形式和有稳定 ID 的错误记录。
- 熟词按本文语境释义；单纯列为重点不算错误；同次误译在多个小节出现只能算一次。
- 校正提取结果，避免错误说明被放到释义里；扫描形式使用原文的实际变形，如 taken off / takes off。
- 原文中不存在的词、句式或总结例句可以留在复盘区，不能插进正文，不能伪造出现次数。

## 3. 制作逐句精读数据

新文章导入后已生成 `content/readings/NNN-slug.json`。如果尚未生成，可执行：

```powershell
node scripts/reading.mjs prepare --id 3
```

脚本按自然段与英文句子建立骨架，不覆盖已有文件。Codex 必须核对自动分句（引号、缩写、分号），再补齐每句翻译和批注。

```json
{
  "articleId": 3,
  "groups": [{ "id": 1, "title": "段落阅读主题" }],
  "units": [{
    "id": "01", "group": 1,
    "english": "The phrase takes off.",
    "translation": "这个说法走红了。",
    "annotations": [{
      "text": "takes off", "label": "take off", "type": "phrase",
      "meaning": "迅速流行；走红",
      "context": "这个说法开始流行起来",
      "note": "按当前语境理解整个词块。"
    }]
  }]
}
```

- `english` 必须是原文；每个 unit 必须有对应 `translation`。
- 翻译精确、朴素，保留 may / can / might / often / seem 等强度，保留角色、条件、否定、转折和时间关系。
- `annotations[].text` 是原文中的精确文字；`label` 可表示词典形式、固定词块或可迁移结构。
- 每条注释必须有 `meaning`、`context`、`note`；不要留“待补充”。
- 原句重复出现同一文字时，设置 `occurrence: 1`、`2` 等，明确标注第几处。
- 同一句批注不可重叠。句式可以用入口词高亮，完整结构放在解释中；避免整句着色。
- 单词用 `vocabulary`，词块用 `phrase`，句式用 `structure`，真实易错用 `error`。
- 只把本次学习资料中的重点放回原文；不把正文变成全词解释或新语法课。
- 正文英文 → 当前批注（点击后）→ 中文翻译；标注看起来仍是原文文字，不做胶囊按钮、浮动提示或弹窗。

## 4. 检查、完成本地发布

```powershell
node scripts/reading.mjs check --id 3
node --test tests/*.test.mjs
node scripts/reading.mjs publish --id 3
```

检查包括：原文没有遗漏或改写、每句有翻译、批注位置准确且不重叠。
`publish` 检查通过后才把草稿转为正式文章并构建；没有精读数据的正式文章会使构建失败。
这些检查保证结构和文本一致，不能替代人工核对译文含义。

## 5. 两轮实际浏览验收

本地预览：`node scripts/serve.mjs`。使用浏览器技能检查。

第一轮在桌面（例如 1280px）与手机 390px 阅读正文并点开批注，检查翻译精度、视觉层级、长句换行与解释的位置；修正发现的问题。

第二轮重新构建并刷新，在两种宽度复核：

- 每个单元有英文和对应翻译，英文比翻译醒目。
- 点击正文标注，解释在同句下方出现；再次点击关闭；同句另点一个词会替换解释。
- 点击跨行词块时点实际文字区域；不可用整个多行元素包围框的空白中心代替用户点击。
- 手机不依赖 hover；解释正常参与排版，没有悬浮到屏幕外或遮住正文。
- 无横向溢出，无控制台错误；首句、中部长句、易错词和末句都检查。
- 保留截图与简短验收记录，检查旧文章、真实错误及词频没有被无关改动。

## 6. 提交、推送、核对线上版本

检查 Git diff，只提交本次内容、流程或相关修正。按用户授权提交到既定仓库并推送 `main`。
检查对应 commit 的 Pages workflow 成功，读取线上 buildId / 当前文章数据，并实际点击至少一条线上批注。
最终给用户该文章的固定网址、完成情况和必要的内容差异说明。

## 维护边界

保持三个主视图和现有阅读模板。无需新增框架、后端、数据库、学习管理或复习功能。
词频只扫描文章原文；批注与翻译不参与词频。生成的 `data` 与 `dist` 不手改。
